# Vocal Coach — Plan 8: README and Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Backend tasks use `backend/.venv/bin/python`; frontend tasks run from `frontend/` with npm; frontend implementers invoke the `design-taste-frontend` skill before UI code. Tasks 1, 2, 3 (backend) and 5, 6 (frontend) touch disjoint files and may run as parallel implementers in one worktree, each committing only its own paths; Task 4 (nginx + runtime config) touches `frontend/` deploy files and `frontend/src/auth` only; Task 7 (docs) runs last.

**Goal:** Close the deferred-hardening list from Plans 1 to 7 and ship the project documentation the spec asks for, so a new operator can run, configure and test Vocal Coach from the root README alone.

**Architecture:** Small, independent hardening slices: Drive job retry via two new `jobs` columns (Alembic `0002`), atomic batch submit, a job dismiss endpoint; a cache lifecycle (prune on delete, size cap, Google retry/backoff, folder listing); upload streaming limits and off-loop DB calls; nginx security headers, JSON 413, DNS resolver and a runtime `/config.json` for Keycloak settings so one image serves any environment; frontend resilience (query retry policy, infinite pagination, upload cancel, job dismiss, coaching indicator, Drive folder navigation, mobile header); a Playwright end-to-end suite against the compose stack; and the root README plus a spec amendments log.

**Tech Stack:** existing stack (FastAPI, SQLAlchemy 2 + Alembic, httpx, React 19, TanStack Query 5, Recharts, nginx 1.27) plus `@playwright/test` as a frontend dev dependency.

**Spec:** `docs/superpowers/specs/2026-10-03-vocal-coach-design.md` §17 (Engineering: README contents, `.gitignore`), §18 step 8 (README, `.env.example`, smoke script, hardening), §9 (comparison, amended here), §10 (jobs), §5 (cache), §14 (deployment).

**Spec amendments made by this plan (appended to the spec as a log in Task 7):**
1. §9: a comparison row's verdict is `unchanged` when `abs(delta)` rounds to `0.0` at the metric's display precision (1 decimal; 2 for `modulation_depth`; 0 for counts), regardless of `min_meaningful_change_pct`. `ComparisonResult` gains `file_names: list[str | null]`.
2. §10: `jobs` gains `drive_file_id` and `drive_modified_time` so Drive jobs can be retried; `DELETE /api/jobs/{id}` dismisses a terminal job (404 for non-terminal or unknown).
3. §5: cache files are removed when the last analysis referencing that Drive file is deleted; total cache size per server is capped by `CACHE_MAX_MB` (default 2048) with least-recently-used eviction before each download; `DRIVE_MAX_MB` (default = `MAX_UPLOAD_MB`) caps Drive downloads. `GET /drive/files` also returns folders (`is_folder: true`, `size: null`) so the browser can navigate.
4. §14: the frontend image reads Keycloak settings at runtime from `/config.json` (generated by the nginx container entrypoint from `KEYCLOAK_URL`, `KEYCLOAK_REALM`, `KEYCLOAK_CLIENT_ID`), replacing the build-time `VITE_KEYCLOAK_*` args; the Vite dev server serves a static `public/config.json`.
5. §17: Node version is 22 and the package manager is npm (not pnpm), matching what the project already uses; dependencies list reflects httpx-based providers (no `openai`, no `google-api-python-client`).

1. **Operator with a fresh clone follows only the root README:** `cp .env.example .env`, generates the two keys, `docker compose up -d --build`, opens `http://localhost:3000`, signs in as demo, uploads a file, sees coaching disabled or enabled depending on config. 3. **Retry of a Drive job after the file changed in Drive:** retry re-fetches metadata, uses the new `modifiedTime`, downloads again, and the new analysis has the new `recorded_at`. Test in Task 1.

5. **Frontend served by one image in two environments (Keycloak on a different host):** the app reads `/config.json` at startup; a missing or malformed config shows a clear "Configuration error" page instead of a blank screen. Test in Task 4.
